# Stateful reconnect E2E fixture

Minimal ASP.NET Core host exercising SignalR stateful reconnect (.NET 8+ Ack/Sequence,
message types 8/9): `AllowStatefulReconnects` on the hub endpoint and a page using the
official browser client with `withStatefulReconnect()`.

This fixture deliberately uses the **official** `@microsoft/signalr` client
(`wwwroot/signalr.min.js`, version 10.0.11, MIT license) instead of the repository's
hand-rolled sample clients: the end-to-end test validates the inspector against the real
client's wire behavior — the same golden-source philosophy as the MessagePack fixtures
generated by the official .NET protocol implementation. The transparent transport resume
(no `onreconnecting` callback, a second WebSocket reusing the connection id) cannot be
reproduced faithfully by a reimplementation without the test becoming circular.

The fixture is test-only: it is not part of the store package allowlist and not part of
`samples/`, which stays dependency-free.

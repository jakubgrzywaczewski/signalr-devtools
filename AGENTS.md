# SignalR Inspector

Chrome and Edge DevTools extension for inspecting ASP.NET Core SignalR traffic.
The extension itself lives in `signalr-inspector/`; `samples/` and
`blazor-signalr-demo/` are .NET fixtures the tests build, `tools/` holds the
MessagePack fixture generator, and `docs/` plus `marketing/` are published
material.

The full maintenance procedure is the `maintain-signalr-inspector` skill. This
file records only what an agent cannot infer from the repository.

## Every commit carries a version bump

This repository has no unversioned commits. Choose exactly one semantic bump per
logical change and apply it with the repository's own tool, from
`signalr-inspector/`:

```bash
npm run version:bump -- <patch|minor|major>
```

Never edit a version by hand. `package.json`, `package-lock.json`, and
`manifest.json` must stay identical; `npm run version:check` enforces that and
the pre-commit hook enforces a bump relative to `HEAD`. Documentation, tests,
chores, dependency maintenance, and CI or security hardening are `patch`.

Record the change in `CHANGELOG.md` under the new version, following the
Keep a Changelog sections already in the file.

## Commit and release are separate operations

Commit every completed logical change. Do **not** tag, push a tag, publish a
GitHub release, or submit to a browser marketplace unless the user asks for that
specific action. Pushing a `v*` tag makes CI publish the GitHub release and
attach the packaged extension by itself, so a tag is a publication, not a
bookkeeping step.

## Validation

The pre-commit hook runs the version policy, strict Biome, the full Vitest
suite, and a Release build of the .NET sample. Never bypass it with
`--no-verify`. Run the narrowest useful check while working and the whole gate
before finishing:

```bash
npm run check          # Biome, warnings are errors
npm run test:coverage  # Vitest with coverage thresholds
npm audit --audit-level=high
```

CI additionally runs Playwright end-to-end tests, secret scanning, and the
packaged-archive check. Node 24 matches CI; `engines` also permits 22 and 26.

## Agent instrumentation

This repository is public and the `ai-agent-toolkit` it depends on is private, so
the instrumentation is deliberately kept out of Git. `.gitignore` excludes
`apm.yml`, `apm.lock.yaml`, `apm_modules/`, `.claude/`, and every deployed skill —
with one deliberate exception, `.agents/skills/maintain-signalr-inspector/`, which
is committed and is the canonical maintenance procedure.

Two consequences worth knowing before you rely on any of it:

- a fresh clone has no APM configuration. Recreate it with `apm install` against
  the private toolkit; the target list and the package pin live only on the
  machine that configured them, so they can differ between machines;
- `build-chrome-extension` and `publish-chrome-extension` are deployed output,
  regenerated by `apm install` and never hand-edited. Change them in
  `ai-agent-toolkit`, release a tag, then move the pin locally.

Anything in `.claude/skills/` or `.claude/agents/` exists on one machine only. A
procedure worth keeping belongs in a toolkit package, not there.

## Ask before deciding

Escalate rather than choosing alone: added host permissions, remote code, new
outbound traffic or telemetry, payload retention, publication, and store
submission.
